# Automated data collection

The raw internship dataset is generated by `src/collect_postings.py`. The
collector queries structured career feeds supplied by Ashby, Lever, Greenhouse,
Amazon Jobs, and Workday; it
does not copy manually written summaries or scrape arbitrary HTML pages.

## Sources

Companies and their public board identifiers are stored in
`config/job_boards.json`. Add or remove a board there without changing the
collector code.

- Ashby: `GET https://api.ashbyhq.com/posting-api/job-board/{board}`
- Lever: `GET https://api.lever.co/v0/postings/{site}?mode=json`
- Greenhouse: `GET https://boards-api.greenhouse.io/v1/boards/{board}/jobs?content=true`
  ([official API documentation](https://docs.greenhouse.io/job-board.html)).
- Amazon Jobs: its public JSON search response, with complete descriptions and
  ISO country codes returned in each result.
- Workday: a configured employer's public career-search and job-detail responses.
  Intel is the first Workday-backed company in this configuration; Intel's
  official application instructions link applicants to that Workday site.

The configuration now contains 32 boards, including Amazon and Intel. This is a configured-board search,
not a search of every company or Google. A board may have no matching openings.

Only publicly listed or published postings returned by these endpoints are
used. No authentication credentials are required.

## Filtering

Collection is US-only. Country metadata is preferred; when it is missing,
the location must explicitly identify the United States (US/USA), or use a
city and uppercase US postal state (for example, Boston, MA). Remote-only,
worldwide, and ambiguous city-only locations are excluded. Ashby secondary
locations are checked individually. Lever's country applies only to its primary
location; other locations need their own US evidence. Greenhouse locations and
attached office locations are checked as well. A multi-location
job is included if it offers at least one confirmed US location, and only those
US locations are saved. This indicates location, not visa or work eligibility.
The CSV includes `country=US`. Conservative matching may omit US jobs whose
board does not supply enough location information.

A posting is retained when:

1. Its title describes data, analytics, machine learning, AI, business
   intelligence, applied/research science, software, computer science, developer,
   frontend, backend, or full-stack work; and
2. Its title or employment type identifies it as an internship or co-op.
   Description-only mentions and graduate roles without internship evidence
   no longer qualify.

The filter is deliberately defined in code so that collection is consistent
and reviewable. It can still produce false positives or miss unusual titles,
so generated data should be reviewed before drawing conclusions.

After filtering and URL deduplication, the collector retains at most five
postings per company by default. When publication timestamps are available,
newer postings are preferred; otherwise title and URL provide a stable order.
Greenhouse update timestamps are not mislabeled as publication dates.
The cap limits employer dominance but does not make this a representative market
sample. Change the cap when needed:

```bash
python -m src.collect_postings --max-per-company 10
```

## Run the collector

Activate the project environment and test the live endpoints without changing
the current CSV:

```bash
python -m src.collect_postings --dry-run
```

Replace the raw dataset after a successful collection:

```bash
python -m src.collect_postings
```

The collector requires at least five valid postings by default and retains no
more than five per company. If too few are found, it exits without replacing
the existing CSV. Individual company errors are reported while the remaining
boards continue.

## Rebuild Steps 3–6

The US collector writes `data/raw/us_internship_postings.csv` by default.
The earlier worldwide snapshot and outputs remain unchanged for comparison.
The default safety minimum remains five; the expanded collector does not require
the earlier small-sample override.

The August 29, 2026 run retained 23 US postings across 13 companies after the
five-per-company cap, including Amazon and Intel results.

After collection, regenerate every derived file and chart:

```bash
python -m src.clean_text --input data/raw/us_internship_postings.csv --output data/processed/us/cleaned_postings.csv
python -m src.extract_skills --input data/processed/us/cleaned_postings.csv --postings-output data/processed/us/postings_with_skills.csv --skills-output data/processed/us/posting_skills.csv
python -m src.analyze_skills --postings data/processed/us/postings_with_skills.csv --skills data/processed/us/posting_skills.csv --output-dir data/processed/us/analysis
python -m src.create_visualizations --analysis-dir data/processed/us/analysis --output-dir reports/figures/us
```

Job listings change and close over time, so rerunning the collector can produce
different counts and charts. The `date_collected`, source URL, provider,
external posting ID, publication time, employment type, and workplace type are
stored with every collected record for traceability.
